# Milestone 2: Cardano on-disk chain database

This milestone adds the `database` crate, a low-level Rust interface for Cardano's on-disk chain
database. The implemented reader traverses immutable blocks chronologically, verifies each block's
CRC32 checksum, and supports caching. A single-writer interface supports append and rollback
of the tip of this immutable-store representation.

## Provided mainnet sample

The `M2` tag includes the first ten complete immutable mainnet file groups in
[`reviewing/M2/mainnet-sample`](M2/mainnet-sample). No external blockchain download is required. The sample
contains 30 database files: ten `.chunk`, ten `.primary`, and ten `.secondary` files. Together they
contain 215,977 blocks and occupy 173,536,873 bytes.

Set the paths used by the remaining commands and verify every file against the committed manifest:

```shell
export M2_REVIEW_DIR="$PWD/.review/M2"
export IMMUTABLE_DB="$PWD/reviewing/M2/mainnet-sample"
mkdir -p "$M2_REVIEW_DIR"

cd "$IMMUTABLE_DB"
if command -v sha256sum >/dev/null 2>&1; then
  sha256sum --check SHA256SUMS
  sha256sum SHA256SUMS
else
  shasum -a 256 --check SHA256SUMS
  shasum -a 256 SHA256SUMS
fi
cd -
```

All 30 checks must report `OK`. The expected SHA-256 of `SHA256SUMS` is:

```text
1c0b0b0972b8271091612d2768f8e7874d8c60e3607d3b7d496c89736b450525
```

The `.primary` files are included for parity with cardano-node and for use by the Haskell reference.
The Rust reader consumes the `.chunk` and `.secondary` files. This is an immutable-history sample,
not a complete runnable node database; ledger snapshots and volatile files are intentionally absent.

## Tests

### Provided immutable database tests

Six sample immutable databases are checked into `database/tests/data`. They cover edge cases like: an empty database,
partial and complete chunks, epoch-boundary blocks, a first-slot edge case, an ambiguous epoch-boundary
case, appends, cross-chunk reads, cache sizes `0`, `1`, `2`, and `10`, truncation, reopening, and cache
invalidation after rollback.

Run the database unit and documentation tests with:

```shell
cargo +1.97.1 test --locked -p database
cargo +1.97.1 test --locked -p database --doc
```

The reproduced local result was 7 passed, 0 failed. Verify all 12 fixture files with this manifest:

```shell
cd database/tests/data
for extension in chunk secondary; do
  for number in $(seq 0 5); do
    stem=$(printf '%05d' "$number")
    sha256sum "${stem}.${extension}"
  done
done | sha256sum
cd -
```

Expected aggregate manifest hash:

```text
1cbe6855bf7dc71028d131a129d45ef545b5f7466e54fcd93b1f4030f7054c7e
```

On macOS, replace each `sha256sum` with `shasum -a 256`.

### Reviewer-selected immutable data

The benchmark checks the secondary index, reads every block from every selected chunk, and validates
every CRC. The example additionally transactions and outputs from every era.
```shell
cargo +1.97.1 bench --locked -p database --bench iterate -- "$IMMUTABLE_DB"
cargo +1.97.1 run --locked --release -p database \
  --example large_outputs -- "$IMMUTABLE_DB"
```

A checksum mismatch, malformed secondary index, I/O error, or block decoding error makes the command
exit fail. Reviewers may also point both commands at any other cardano-node `immutable` directory.

## Correctness against the Haskell reference

The following builds the `db-analyser` executable from the exact Consensus release used by Cardano
Node `11.0.1`, obtains the matching mainnet configuration, and validates every block in the same
partial database. GHC `9.6` and Cabal `3.8` or `3.12` are required by the Cardano Node release.

```shell
mkdir -p "$M2_REVIEW_DIR/reference"
export CARDANO_DB="$M2_REVIEW_DIR/cardano-db"
mkdir -p "$CARDANO_DB"
ln -s "$IMMUTABLE_DB" "$CARDANO_DB/immutable"

git clone https://github.com/IntersectMBO/ouroboros-consensus.git \
  "$M2_REVIEW_DIR/reference/ouroboros-consensus"
git -C "$M2_REVIEW_DIR/reference/ouroboros-consensus" \
  checkout --detach c87aa760001e60f0f0d3353f793eb089adb917e7

git clone https://github.com/IntersectMBO/cardano-node.git \
  "$M2_REVIEW_DIR/reference/cardano-node"
git -C "$M2_REVIEW_DIR/reference/cardano-node" \
  checkout --detach 97036a66bcf8c89f687ae57a048eecc0389977ef

cd "$M2_REVIEW_DIR/reference/ouroboros-consensus"
cabal update
cabal build exe:db-analyser
DB_ANALYSER="$(cabal list-bin exe:db-analyser)"
cd -

"$DB_ANALYSER" \
  --db "$CARDANO_DB" \
  --config "$M2_REVIEW_DIR/reference/cardano-node/configuration/cardano/mainnet-config.json" \
  --in-mem \
  --db-validation validate-all-blocks \
  --count-blocks \
  2>&1 | tee "$M2_REVIEW_DIR/db-analyser-mainnet-00000-00009.txt"
```

The reference command was run successfully on 27 July 2026 with GHC `9.6.7`, Cabal `3.12.1.0`,
Ouroboros Consensus commit `c87aa760001e60f0f0d3353f793eb089adb917e7`, and the mainnet
configuration from Cardano Node commit `97036a66bcf8c89f687ae57a048eecc0389977ef`. With
`--db-validation validate-all-blocks`, `db-analyser` exited successfully and counted 215,977 blocks,
matching the Rust run. It reported an immutable tip at slot 215,999 with block hash
`ff3f37d545b0a933f7556abdbcc91c096147ebf5332b5e512083906726b2bf19`.

The complete output is committed as
[`reviewing/M2/db-analyser-mainnet-00000-00009.txt`](M2/db-analyser-mainnet-00000-00009.txt).
Its SHA-256 is:

```text
50b66a102fc77f8963b5d976d1b9ac4c544d90d2b7edb962506f639ee6bb45f0
```

These results confirm that all blocks in the committed sample pass the pinned Haskell reference
validation and that both implementations count the same number of blocks. The report and checksum
must also be attached to the M2 GitHub Release as acceptance evidence.

## Benchmark

`database/benches/iterate.rs` reads the complete selected range,
validates each block and its CRC and reports performance metrics.

Generate a report with:

```shell
cargo +1.97.1 bench --locked -p database --bench iterate -- "$IMMUTABLE_DB" \
  2>&1 | tee "$M2_REVIEW_DIR/database-iterate-mainnet-00000-00009.txt"
```

The acceptance thresholds are at least 150,000 blocks/minute and at most 1.5 GiB RSS on a
machine with 8 CPU cores and 16 GiB RAM. The following supplemental run was reproduced while drafting
this document:

| Property | Observed value |
| --- | ---: |
| Machine | Apple M1 MacBook Pro, 8 CPU cores, 16 GiB RAM, macOS 26.5.2 |
| Dataset | mainnet immutable `00000`-`00009` |
| Blocks | 215,977 |
| Dataset bytes | 173,536,873 |
| Elapsed | 41.088 ms |
| Throughput | 315,386,337 blocks/minute |
| RSS at completion | 27.05 MiB |

This run exceeds both thresholds by a wide margin.
The machine used is a M1 MacBook Pro with 8 CPU cores and 16 GiB RAM.
